# Spec Delta

## Purpose

Olist 공개 데이터를 개발용 MySQL의 olist DB에 넣고, 날짜를 최근으로 옮겨 "지난 7일" 같은 상대 기간 질문이 파일럿과 같은 방식으로 답해지게 한다. 근거는 아키텍처 문서 8장이다.

## ADDED Requirements

### Requirement: Olist 적재 (F-002)

시드 명령은 `data/raw/olist/`의 Olist CSV 파일들을 olist DB의 테이블로 넣어야 한다(SHALL). 다시 실행하면 테이블을 비우고 처음부터 다시 넣어, 몇 번을 돌려도 결과가 같아야 한다(SHALL). 필요한 CSV가 없으면 아무것도 바꾸지 않고, 없는 파일 이름과 받는 방법을 알려야 한다(SHALL). 분석 대상 DB의 읽기 전용 계정 권한은 바꾸지 않는다.

#### Scenario: 처음 시드
- **WHEN** CSV가 모두 있는 상태에서 시드한다
- **THEN** olist DB의 테이블마다 CSV의 행이 모두 들어간다

#### Scenario: 다시 시드
- **WHEN** 이미 시드한 DB에 다시 시드한다
- **THEN** 행 수가 두 배가 되지 않고 처음 시드와 같다

#### Scenario: CSV가 없음
- **WHEN** 주문 CSV가 없는 상태에서 시드한다
- **THEN** DB는 그대로이고, 없는 파일 이름과 Kaggle에서 받으라는 안내가 나온다

### Requirement: 날짜를 최근으로 옮기기 (F-002)

시드 명령은 마지막 주문일이 어제가 되도록 간격을 계산하되 7의 배수로 내려, 그 간격을 모든 날짜·시각 컬럼에 더해야 한다(SHALL). 그래서 요일은 원본과 같고, 마지막 주문일은 어제이거나 그보다 최대 6일 전이다. 다시 시드하면 원본 CSV에서 그날 기준으로 다시 계산해, 간격이 쌓이지 않아야 한다(SHALL).

#### Scenario: 7일 단위로 옮김
- **WHEN** 원본의 마지막 주문일과 어제 사이가 10일이다
- **THEN** 모든 날짜가 7일 뒤로 옮겨지고, 마지막 주문일은 어제보다 3일 전이 된다

#### Scenario: 요일 유지
- **WHEN** 시드한 뒤 아무 주문의 요일을 원본과 비교한다
- **THEN** 요일이 같다

#### Scenario: 다시 시드해도 쌓이지 않음
- **WHEN** 같은 날 두 번 시드한다
- **THEN** 두 번째 결과의 날짜는 첫 번째와 같다
