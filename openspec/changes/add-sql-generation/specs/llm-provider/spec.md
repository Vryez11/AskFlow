# Spec Delta

## Purpose

LLM 공급자와 모델을 코드 수정 없이 설정으로 고르고, 한 공급자가 멈추면 데이터 정책이 허용하는 다음 공급자로 자동으로 넘기고 살아나면 되돌린다. 근거는 아키텍처 문서 7장이다.

## ADDED Requirements

### Requirement: 설정으로 공급자 고르기 (F-002)

시스템은 단계(SQL 생성 등)마다 LLM 공급자와 모델 목록을 순서대로 설정 파일에서 읽어야 한다(SHALL). 공급자의 API 키는 설정 파일에 쓰지 않고 환경 변수로 받아야 한다(SHALL). 키가 없는 공급자는 부를 수 없는 것으로 보고 다음 순위로 넘긴다. 앱은 키가 없어도 시작해야 한다(SHALL).

#### Scenario: 1순위 공급자
- **WHEN** SQL 생성 단계에 Gemini 3.8 Flash, Gemini 3.5 Flash-Lite 순서를 설정하고 둘 다 정상이다
- **THEN** 요청은 Gemini 3.8 Flash로 가고, 응답에 답한 공급자와 모델이 Gemini 3.8 Flash로 남는다

#### Scenario: 설정만 바꿔 공급자 바꾸기
- **WHEN** 설정의 1순위를 Claude 모델로 바꾸고 앱을 다시 시작한다
- **THEN** 코드를 고치지 않아도 요청이 Claude로 간다

#### Scenario: 키가 없는 공급자
- **WHEN** 1순위 공급자의 API 키 환경 변수가 비어 있다
- **THEN** 앱은 시작하고, 요청은 다음 순위로 가며, 기록에 1순위를 건너뛴 이유로 키 없음과 그 환경 변수 이름이 남는다

### Requirement: 다음 순위로 넘기는 실패 (F-002)

시스템은 요청 한도 초과(429), 서버 오류(5xx), 연결 실패, 시간 초과, 안전 분류기의 거절이면 다음 순위로 넘겨야 한다(SHALL). 요청 형식 오류(400)와 인증 오류(401, 403)는 설정이나 코드 문제라 넘기지 않고 오류로 돌려주어야 한다(SHALL). 응답은 왔지만 정해진 출력 형식을 지키지 않으면 같은 공급자에 한 번 다시 묻고, 그래도 어기면 다음 순위로 넘겨야 한다(SHALL).

#### Scenario: 요청 한도 초과
- **WHEN** 1순위가 429를 돌려준다
- **THEN** 같은 요청이 2순위로 가고, 기록에 전환과 그 이유가 남는다

#### Scenario: 인증 오류
- **WHEN** 1순위가 401을 돌려준다
- **THEN** 2순위로 넘기지 않고 "LLM 설정 오류"와 확인할 환경 변수 이름을 돌려준다

#### Scenario: 형식을 어긴 응답
- **WHEN** 1순위의 응답이 정해진 형식을 두 번 연속 어긴다
- **THEN** 1순위에 한 번 다시 물은 뒤 2순위로 넘긴다

### Requirement: 서킷 브레이커 (F-002)

시스템은 공급자·모델마다 최근 호출의 실패 비율을 보고, 문턱을 넘으면 정한 시간 동안 그 공급자·모델을 부르지 않고 곧바로 다음 순위로 넘겨야 한다(SHALL). 시간이 지나면 몇 번만 시험 삼아 보내 성공하면 다시 원래 순위로 쓰고, 실패하면 다시 쉬어야 한다(SHALL). 429 응답이 기다릴 시간을 알려 주면 적어도 그 시간 동안은 부르지 않아야 한다(SHALL). 문턱, 쉬는 시간, 시험 횟수는 설정으로 바꿀 수 있다.

#### Scenario: 계속 실패하는 공급자를 건너뜀
- **WHEN** 1순위가 문턱을 넘게 실패한 뒤 새 요청이 온다
- **THEN** 1순위를 부르지 않고 곧바로 2순위로 보낸다

#### Scenario: 살아나면 되돌림
- **WHEN** 쉬는 시간이 지난 뒤 1순위에 시험 삼아 보낸 요청이 성공한다
- **THEN** 다음 요청부터 다시 1순위가 받는다

#### Scenario: 기다릴 시간을 지킴
- **WHEN** 1순위가 30초 뒤에 다시 하라는 429를 돌려준다
- **THEN** 30초가 지나기 전에는 1순위를 부르지 않는다

### Requirement: 모두 실패하면 (F-002)

목록의 모든 공급자·모델이 실패하거나 쉬는 중이면, 시스템은 "LLM 사용 불가" 오류를 돌려주어야 한다(SHALL). 오류에는 공급자마다 실패 이유와 확인할 설정 키나 환경 변수가 있어야 하고, API 키 값은 없어야 한다(SHALL).

#### Scenario: 두 공급자 모두 실패
- **WHEN** 1순위와 2순위가 모두 5xx를 돌려준다
- **THEN** "LLM 사용 불가" 오류가 돌아오고, 두 공급자의 실패 이유가 담긴다

### Requirement: 데이터 정책에 따른 제한 (F-002)

설정은 데이터 정책(공개 데이터 또는 회사 데이터)과 모델마다 등급(무료 또는 유료)을 가져야 한다(SHALL). 데이터 정책이 회사 데이터인데 어느 단계의 목록에든 무료 등급 모델이 있으면 앱은 시작하지 않고 잘못된 설정 키를 알려야 한다(SHALL). 등급을 적지 않은 모델은 무료로 본다.

#### Scenario: 공개 데이터와 무료 등급
- **WHEN** 데이터 정책이 공개 데이터이고 무료 등급 모델만 있다
- **THEN** 앱이 시작한다

#### Scenario: 회사 데이터와 무료 등급
- **WHEN** 데이터 정책이 회사 데이터이고 목록에 무료 등급 모델이 하나 있다
- **THEN** 앱은 시작하지 않고, 그 모델과 설정 키를 알려 준다

#### Scenario: 등급을 적지 않음
- **WHEN** 데이터 정책이 회사 데이터이고 등급을 적지 않은 모델이 있다
- **THEN** 무료로 보아 앱은 시작하지 않는다
