# Spec Delta

## Purpose

분석 대상 DB를 설정 파일로 연결하고, 연결이 되었는지와 계정이 안전한지를 개발자가 홈에서 바로 확인할 수 있게 한다. 목표와 수용 기준은 PRD F-003을 따른다.

## ADDED Requirements

### Requirement: 설정 파일로 연결 (F-003)

시스템은 분석 대상 DB의 접속 주소, 스키마, 계정, 허용 테이블, 개인정보 컬럼, 행 수 상한, 실행 시간 상한을 설정 파일에서 읽어야 한다(SHALL). 비밀번호는 설정 파일에 직접 쓰지 않고 환경 변수로 받아야 한다(SHALL). 설정은 앱을 시작할 때 읽고, 바꾸면 다시 시작해야 반영된다.

#### Scenario: 설정한 DB에 연결
- **WHEN** 설정 파일에 접속 주소·스키마·계정을 적고, 비밀번호 환경 변수를 넣은 뒤 앱을 시작한다
- **THEN** 시스템은 그 DB에 연결하고, 연결 상태를 "연결됨"으로 둔다

#### Scenario: 상한을 설정하지 않음
- **WHEN** 행 수 상한과 실행 시간 상한을 설정 파일에 적지 않고 앱을 시작한다
- **THEN** 행 수 상한은 1,000행, 실행 시간 상한은 10초가 적용된다

#### Scenario: 허용 테이블을 설정하지 않음
- **WHEN** 허용 테이블 목록을 비워 두고 앱을 시작한다
- **THEN** 설정한 스키마의 모든 테이블과 뷰가 허용 테이블이 된다

#### Scenario: 잘못된 상한 값
- **WHEN** 행 수 상한이나 실행 시간 상한을 0 이하로 적고 앱을 시작한다
- **THEN** 앱은 시작하지 않고, 어떤 설정 키가 잘못됐는지 알려 준다

### Requirement: 연결 실패에도 앱은 뜬다 (F-003)

분석 대상 DB에 연결하지 못해도 앱은 시작되어야 한다(SHALL). 연결 상태는 "연결 실패"로 두고, 원인과 확인할 설정 키를 함께 남겨야 한다(SHALL).

#### Scenario: 비밀번호가 틀림
- **WHEN** 비밀번호 환경 변수가 틀린 채로 앱을 시작한다
- **THEN** 앱은 시작되고, 연결 상태는 "연결 실패", 원인은 인증 실패, 확인할 설정은 계정 이름과 비밀번호 환경 변수다

#### Scenario: DB에 닿지 않음
- **WHEN** 접속 주소의 호스트나 포트에 DB가 없는 채로 앱을 시작한다
- **THEN** 연결 상태는 "연결 실패", 원인은 접속 불가, 확인할 설정은 접속 주소다

#### Scenario: 스키마가 없음
- **WHEN** 설정한 스키마가 DB에 없거나 계정이 그 스키마에 접근할 수 없다
- **THEN** 연결 상태는 "연결 실패", 원인은 스키마 없음 또는 권한 없음, 확인할 설정은 스키마 이름이다

#### Scenario: 허용 테이블이 스키마에 없음
- **WHEN** 허용 테이블 목록에 스키마에 없는 테이블이 있다
- **THEN** 연결 상태는 "연결 실패", 원인은 없는 테이블 이름이고, 확인할 설정은 허용 테이블 목록이다

### Requirement: 쓰기 권한 경고 (F-003)

시스템은 연결할 때 접속 계정의 권한을 확인해야 한다(SHALL). 계정에 조회(SELECT, SHOW VIEW)가 아닌 권한이 분석 대상 스키마나 전체 DB에 하나라도 있으면, 연결은 유지하되 연결 상태에 쓰기 권한 경고와 발견한 권한 이름을 남겨야 한다(SHALL). 권한을 확인하지 못하면 확인하지 못했다는 경고를 남겨야 한다(SHALL).

#### Scenario: 읽기 전용 계정
- **WHEN** SELECT와 SHOW VIEW 권한만 있는 계정으로 연결한다
- **THEN** 연결 상태에 쓰기 권한 경고가 없다

#### Scenario: 쓰기 권한이 있는 계정
- **WHEN** 분석 대상 스키마에 INSERT 권한이 있는 계정으로 연결한다
- **THEN** 연결 상태는 "연결됨"이고, 쓰기 권한 경고에 INSERT가 들어 있다

#### Scenario: 전체 권한 계정
- **WHEN** 모든 DB에 ALL PRIVILEGES가 있는 계정으로 연결한다
- **THEN** 연결 상태에 쓰기 권한 경고가 있다

### Requirement: 연결 상태 조회 (F-003)

시스템은 연결 상태를 조회하는 API를 제공해야 한다(SHALL). 응답에는 연결 여부, 허용 테이블 수, 용어 수, 쓰기 권한 경고, 마지막으로 확인한 시각이 있고, 연결에 실패했으면 원인과 확인할 설정 키가 있어야 한다(SHALL). 응답에는 비밀번호를 넣지 않아야 한다(SHALL NOT). 조회할 때마다 연결을 다시 확인해, 설정을 고치지 않고 DB만 살아난 경우에도 상태가 바뀌어야 한다(SHALL).

#### Scenario: 정상 연결 상태
- **WHEN** 허용 테이블이 9개인 DB에 연결된 상태에서 연결 상태를 조회한다
- **THEN** 응답은 연결됨, 테이블 수 9, 용어 수, 쓰기 권한 경고 없음을 담는다

#### Scenario: 용어 사전이 아직 없음
- **WHEN** 용어 사전이 설정되지 않은 상태에서 연결 상태를 조회한다
- **THEN** 용어 수는 0이다

#### Scenario: 나중에 살아난 DB
- **WHEN** DB가 꺼진 채 앱을 시작한 뒤 DB를 켜고 연결 상태를 다시 조회한다
- **THEN** 응답은 연결됨으로 바뀐다

#### Scenario: 비밀 값은 응답에 없음
- **WHEN** 어떤 상태에서든 연결 상태를 조회한다
- **THEN** 응답 어디에도 비밀번호 값이 없다

### Requirement: 홈의 연결 상태 표시 (F-003)

홈 화면은 데이터 연결 상태를 보여 주어야 한다(SHALL). 연결되면 연결됨 표시, 테이블 수, 용어 수를 보이고, 쓰기 권한 경고가 있으면 경고와 권한 이름을 눈에 띄게 보여야 한다(SHALL). 연결에 실패하면 원인과 확인할 설정을 보여야 한다(SHALL). 화면의 글은 한국어다.

#### Scenario: 연결됨
- **WHEN** 연결 상태 API가 연결됨, 테이블 9개, 용어 0개를 돌려줄 때 홈을 연다
- **THEN** 홈에 "연결됨", 테이블 9개, 용어 0개가 보인다

#### Scenario: 쓰기 권한 경고
- **WHEN** 연결 상태 API가 쓰기 권한 경고(INSERT, UPDATE)를 돌려줄 때 홈을 연다
- **THEN** 홈에 쓰기 권한 경고와 INSERT, UPDATE가 보인다

#### Scenario: 연결 실패
- **WHEN** 연결 상태 API가 연결 실패와 원인, 확인할 설정 키를 돌려줄 때 홈을 연다
- **THEN** 홈에 연결 실패, 원인, 확인할 설정 키가 보인다

#### Scenario: 상태 API에 닿지 않음
- **WHEN** 연결 상태 API 호출이 실패할 때 홈을 연다
- **THEN** 홈에 연결 상태를 불러오지 못했다는 안내가 보이고, 나머지 화면은 그대로 쓸 수 있다
